# Workspace: tue.bi

Minimal personal Jekyll site for the domain **tue.bi**, hosted on GitHub Pages.
The site itself is a placeholder — mostly default Jekyll boilerplate with a
few personal touches (an inside joke about Tübingen's "anthem" in the README,
"Ach, Schee." on the homepage). Treat content changes as low-stakes.

## Layout

- `CNAME` — GitHub Pages custom domain file, must contain exactly `tue.bi`.
- `front_page/` — the actual Jekyll site (uses the default `minima` theme,
  `jekyll-feed` plugin).
  - `_config.yml` — site settings (title, url, baseurl `/front_page/`).
  - `index.markdown`, `about.markdown` — the two real pages.
  - `_posts/` — Jekyll blog posts (currently just the default welcome post).
  - `404.html` — custom not-found page.
  - `_site/` — build output, generated by Jekyll, not hand-edited.

## Local development

```bash
cd front_page
bundle exec jekyll serve
```

Restart the server after editing `_config.yml` (not hot-reloaded).

## Deploy

Plain GitHub Pages — pushing to the default branch is the deploy mechanism.
No CI/build pipeline beyond what GitHub Pages runs itself.

## Gotchas

- `baseurl` in `_config.yml` is set to `/front_page/`, which only makes sense
  if GitHub Pages is configured to serve from the `front_page/` subfolder (or
  it's built manually into a docs/output dir) — double-check this if links
  break, since `url` is `https://tue.bi` (root domain, no subpath).
- The CNAME file has been recreated a few times in git history (see recent
  commits) — don't delete it, it's what makes `tue.bi` resolve to this repo
  instead of the default `github.io` URL.
