# Workspace: tue.bi

Personal Jekyll site for the domain **tue.bi**, hosted on GitHub Pages. The
homepage is a small landing page for the Educaido app (library occupancy info
for Tübingen), with a German/English toggle. The rest is low-stakes personal
boilerplate (an inside joke about Tübingen's "anthem" in the README, an
Impressum page).

## Layout

The Jekyll site lives at the **repo root** (uses the default `minima` theme,
`jekyll-feed` plugin) — this matches how GitHub Pages actually builds it
(whole-repo source, no subfolder support in the plain branch-deploy model).

- `CNAME` — GitHub Pages custom domain file, must contain exactly `tue.bi`.
- `_config.yml` — site settings (title, url, `baseurl: ""`). Also carries a
  custom `exclude:` list — since Jekyll's own `exclude:` default is
  *replaced*, not extended, by any value set here, this list re-includes
  Jekyll's usual defaults (Gemfile, vendor/, .sass-cache/, …) plus repo files
  that shouldn't ship to the built site (`CLAUDE.md`, `README.md`, and the
  full-res source images `educaido-logo.png` / `tuebi-logo.jpeg`).
- `index.markdown` — the Educaido landing page (logo, DE/EN toggle, App
  Store/Google Play links). `about.markdown`, `impressum.markdown` — the
  other two real pages.
- `_includes/header.html` — overrides minima's default header to show the
  `tuebi-logo.png` image instead of a plain text site title.
- `assets/main.scss` — overrides minima's default styling (`@import
  "minima";` plus custom rules for the hero section, buttons, language
  toggle, site logo).
- `assets/images/` — web-sized logos actually used by the site
  (`educaido-logo.png`, `tuebi-logo.png`). The full-resolution originals
  (`educaido-logo.png`, `tuebi-logo.jpeg`) live at the repo root as source
  masters and are excluded from the build.
- `404.html` — custom not-found page.
- `_site/` — build output, generated by Jekyll, not hand-edited, gitignored.

## Local development

```bash
bundle exec jekyll serve
```

Restart the server after editing `_config.yml` (not hot-reloaded).

## Deploy

Plain GitHub Pages — pushing to the default branch is the deploy mechanism.
No CI/build pipeline beyond what GitHub Pages runs itself. GitHub Pages
builds the **whole repository** as the Jekyll source (there is no way to
point plain branch-deploy Pages at a subfolder) — this is why the site lives
at the repo root rather than in a subfolder like `front_page/`. If a future
`theme:` or `plugins:` change ever seems to have no effect in production,
check that `_config.yml` is still at the root the real build actually reads
(the GitHub Pages build log states its `Source:` path).

## Gotchas

- The CNAME file has been recreated a few times in git history (see recent
  commits) — don't delete it, it's what makes `tue.bi` resolve to this repo
  instead of the default `github.io` URL.
- Any new SCSS partial imported in `assets/main.scss` must actually exist in
  the active theme's `_sass/` (minima, per `_config.yml`) — a missing import
  is a hard Jekyll build error that fails the GitHub Pages deploy outright,
  not just a broken stylesheet.
